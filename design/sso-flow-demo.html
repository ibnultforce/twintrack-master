    How the pieces connect

    Three places the demo adjusts your description

    The flow you described is unchanged for the user. These three details change underneath, each for a security or reliability reason. Each one has a button above so you can see it happen.

    You describedThe demo doesWhySee it
    Redirect to the module with the access tokenThe redirect URL carries no token. As HR loads, it calls POST /auth/refresh, the browser adds the refresh cookie, and Master returns an access token.URLs end up in browser history, server logs and Referer headers. The same call also covers a page reload and someone typing hr.twintrack.com directly.Open HR and watch the address bar and the first log entry.
    Each module validates the tokenThe Master API validates the token on every call. HR's frontend only uses the answers to decide which tabs and buttons to show.Modules have frontends only, and anything running in the browser can be edited by the user. A check there can't protect data.Edit my token
    Master keeps each user's permissionsExactly that, and the token doesn't copy them. It holds identity only, and Master reads permissions from the database on each call.Master answers every call anyway, so a role change applies on the next call. The earlier PeopleHub design put permissions in the token, where they stayed stale until the next refresh.Remove my HR role

    API routes in this demo

    All of them run on Master, at api.twintrack.com. Signed routes need a valid token; Private routes also need the named permission.

    Decisions

    QuestionDecisionWhat it affects
    Where does the API live?api.twintrack.com, as shown here.The refresh cookie stays with that one host, away from every frontend. Each frontend's address must be on the API's CORS allow-list.
    Who can change a person's HR role?HR staff with the Master role hr-access, as well as Master admins and super admins.In the demo that means Sabbir and Farhana. hr-access covers HR roles only, and nobody can change their own access.
    How long do tokens and sessions last?15-minute access tokens. Sessions end after 7 days without use, and after 30 days regardless.How often people must log in again, and how long a stolen cookie could be useful.
    How do you keep Master available?Recommended, not yet decided: run at least two API instances behind a load balancer from day one.All login, permission and module traffic goes through one backend. If it's down, every module is down.
